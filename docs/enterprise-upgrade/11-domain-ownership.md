# Domain ownership contracts

These contracts state the destination owner and current operational responsibilities. They do not claim exclusive database permissions already exist. The [database matrix](14-database-ownership.md) records exceptions.

| Service | Owned operations | Authentication and authorization | Dependency failure behavior | Operations and compatibility obligations |
|---|---|---|---|---|
| Gateway | Route dispatch, correlation, edge headers and availability | Forwards cookie/Bearer credentials. Removes client identity assertions. Domain services verify JWTs and object access | Refusal 502, upstream timeout 504; no write retries. Readiness can degrade globally while available domain routes still work | Maintain route precedence, aliases, CORS and WS upgrade. Drain connections on shutdown |
| Identity | Register/login/bootstrap/refresh/logout, account/preferences | Authenticated subject owns preferences; passwords required for sensitive operations. Server persists role and token version | Mongo failure fails startup/readiness; public auth operations cannot succeed without DB | Signing keys and session policy, password hashing, cookie/CSRF contract. Legacy profile and relationship aliases stay compatible |
| Quiz | Create/edit/publish/read metadata and questions, import generation, quiz search | Owner/admin for private content. Guests access public/unlisted content per current policy | Attempt relay fails boundedly with 503/504, without executing a local substitute | Own question content and immutable identifiers. File cleanup stays local. Keep authoring and result URLs working |
| Attempt | Start/recover, answers, progress/time, submit, results, timer finalization | End-service JWT/account checks plus user or opaque guest-session ownership. Challenge participation requires authentication. Creator uses practice attempts | DB errors fail operations. No retry or fallback scoring owner | Own valid attempt transitions, timing and scoring. One embedded expiry scheduler per process, with non-overlap guard. Replica race fencing remains open |
| Challenge | Competitive definition/draft/publication, access mode, question snapshot and rank projection | Owner for changes; public published records for discovery. Private/restricted rankings unavailable. Scores/ranks sealed until deadline | DB failure fails request. Rank cache is optional and local | Preserve 10-question cap, strict timing, single participant attempt and creator-practice exclusion. Read execution outcomes from Attempt authority |
| Social | Relationships, interactions/comments, feeds, notifications and read state | Subject ownership, profile privacy, public content policy. Legacy DM alias forwards original credentials | Messaging failure produces failure, never arbitrary-recipient fallback | Own relationship/interaction semantics; derived counters require reconciliation. Notifications remain a module |
| Message | Conversation membership, DM privacy, history, read state and mutations | Participant checks and recipient messaging preferences on both HTTP and WS. Session revocation checked per socket event | Bounded queries/budgets. HTTP remains usable during live-update recovery | Idempotent sender/client IDs; stable cursors; quote/attachment revocation. Single-replica boundary until Step 18 |
| Parser | Upload ownership, file validation, parsing/mapping state | Optional JWT with guest-session ownership where supported; validation before persistence | File errors return failures. Do not create successful quizzes from failed parsing | Own temporary source files and parser state, preserve import schema. Malicious-archive tests/dependency remediation in Step 06 |
| Media | Authenticated upload/delete, validated image variants, delivery | Backend asset ownership on mutations. Delivery/privacy requires fuller lifecycle design | Reject invalid files/URLs; filesystem and DB persistence must stay consistent | Storage volume, MIME/signature validation, size limits. No implied private chat attachment service |
| Admin | RBAC, report workflow, moderation/audit and health dashboard | Persisted account role or AdminMembership/AdminRole permission, backend permission middleware on privileged operations | Required DB unavailable means failure. Health requests have deadlines | Own privileged audit records and moderation intent. Cross-domain raw writes remain controlled exceptions pending owner APIs |

Identity owns credentials, account status, username, display name, avatar reference, account-wide preferences and privacy primitives. Social owns relationships and social activity. Public profile responses are views over Identity plus Social data, not a second authoritative user record. A field-level schema/projection registry and owner APIs are required before database separation.

Attempt owns challenge attempt validity, submission transitions and finalization decisions. Challenge owns the definition and deadline. Its leaderboard is a read projection and cannot accept submissions. Attempt's worker currently writes the derived `challengeStatus = ended` field on the existing quiz record as a compatibility exception. It must not change author-defined deadlines or question content. Legacy challenge authoring URLs in Quiz remain supported pending Step 07 consolidation.

Synchronous privacy decisions require fresh authoritative metadata. Derived counts, activity, search tags and notifications may become eventually consistent through versioned owner events, but permissions must not fail open. Schema copies need explicit policy fields. The missing moderation field repaired in Step 02 demonstrates why a shared database alone does not guarantee equivalent policy.
