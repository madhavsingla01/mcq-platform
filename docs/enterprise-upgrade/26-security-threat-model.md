# Identity and privacy threat model

Protected assets include account credentials, unpublished quiz content, guest attempt keys, pre-deadline results, private conversations and media, and administrator privileges. Threat actors include anonymous callers, authenticated users outside a resource's access policy, users replaying stolen credentials, hostile web origins, and operators of compromised downstream services.

| Severity | Threat and evidence | Implemented control | Remaining risk |
|---|---|---|---|
| High | Replayed refresh token and two requests that both appeared valid | Compare-and-swap with a digest at rest, unique refresh tokens, current account version check | Existing raw values migrate on next rotation. One active refresh credential per account |
| High | Cookie writes accepted with empty CSRF pairs | Nonempty matching values in Admin and Challenge, origin enforcement at gateway and Auth, image writes use Media cookie checks | Production cross-origin browser and ingress behavior needs verification |
| High | Old access tokens accepted without consistent account checks | HS256 and claim checks across services. Media image access checks the current account. Socket events and idle sessions revalidate | Passive socket delivery has a polling window. Signing keys remain shared |
| High | Creator or participant could derive sealed challenge outcomes | Result access, analytics and attempt-list gates. Masked averages in both payloads and score sorts. Sealed results excluded from overview and activity | Benchmark score-based queries and audit privileged and cross-service projections in Step 04 |
| High | Private content exposed by historical notification and message references | Current visibility checks, payload redaction and a narrow mark-read response | Legacy public images and parser files require a separate storage privacy review |
| High | An old global role membership could continue to authorize a demoted administrator. A delegated role with `manage_roles` could grant itself the global role | Global role changes require current global authority. Both promotion and demotion revoke prior sessions. Recognized legacy global membership copies no longer grant access on their own | Review manually provisioned legacy memberships in staging. Explicit delegated roles remain valid for their assigned duties |
| High | Admin overview and detail responses included audit or report entries without the corresponding permission | Apply the dedicated audit and report checks to embedded results as well | Review external retention and access to production audit storage |
| Medium | Stolen guest attempt key exposed in serialized attempts | Remove the key from attempt responses and constrain guest history to guest attempts | Guest attempts still use a bearer-like session key. Its entropy and migration need separate review |
| Medium | Credential abuse with guessed identifiers and spoofed forwarded IP. Refresh accepted arbitrary body identifiers as limiter keys | Atomic failed-login counts, comparable password work, independent IP budget, verified actor keys where appropriate, and explicit trusted proxy configuration | Lockout and duplicate-registration responses can disclose account existence. Counters are process-local |
| Medium | Failed desktop logout displayed a signed-out state while the server session could remain valid | Keep the active session visible and offer retry until logout is confirmed. Ignore late bootstrap results after a newer local auth action | Cross-tab refresh races remain possible |
| Medium | Forged role or service header | Gateway strips asserted identity. Domains check signed session and persisted permissions | Private service network and narrower DB roles must be enforced during deployment |
| Low | New build removes JavaScript still referenced by an open tab | Desktop reloads the current route once per build on a recognized module preload failure | Tabs opened before the handler shipped require one manual refresh. Application drafts should continue using their existing autosave behavior |

The [existing risk register](05-security-and-risk-register.md) remains the baseline for dependencies, storage, replica scaling and operations. Review guidance came from OWASP ASVS 5.0 and the API Security Top 10, including object authorization and broken authentication.
